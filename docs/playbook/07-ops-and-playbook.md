## 7. 账号保活与自愈

### 7.1 静态快照 `cookies.json` 会过期
- 生图服务原用静态快照，快照过期就 `UNAUTHENTICATED`。
- **修法**：**统一到一个 cookie 源**——直接读同一个 Firefox profile（三件套），读不到才回退快照。

### 7.2 "重启就好"会掩盖真问题
- 每次重启都恢复，说明有东西在周期性破坏（如 `TempDirCleaner` 把 temp 空目录 rmdir 掉，而插件保存前不 `makedirs`）。
- **修法**：定位到根因再改（一行 `os.makedirs(..., exist_ok=True)` 比"加个看门狗重启"靠谱）。

### 7.3 别批量重启"全家桶"
- 一次 `stop` 掉 gemini-webapi + mihomo + frpc + timer，会把互相依赖的服务一起打死，恢复要很久。
- **纪律**：一次只动一个服务，动完立刻验证。

## 8. 观测与验收（可复用）

### 8.1 三层证据法
1. **服务端日志**：请求是否到达、改写是否命中、上游状态码；
2. **浏览器侧**：`outerHTML` 里有没有注入标记、iframe 是否撑开、有没有消息往返；
3. **上游直连对照**：用同一份 cookie 直接打上游，确认账号/资源本身是否有效。

三者矛盾 = 中间有缓存或改写没生效。

### 8.2 全量自检脚本（21 项）
`fedora-home/scripts/f44-350-mirror-selfcheck.py`（root 运行）：服务/凭据(WAL)/入口/认证/写链路/性能/并发/日志回归/关联服务。退出码 0 = 全通过。

### 8.3 浏览器自动化没有 JS 执行能力时怎么办
- 在服务端注入一个**只在 `?__diag=1` 时生效**的诊断浮层，把需要的内部状态（iframe 尺寸、`contentDocument` 摘要、`__shieldLog`、消息类型）写进一个 `position:fixed` 的 div；
- 然后用浏览器工具的 DOM 快照/截图读取。
- 排查完记得把诊断代码摘掉（本次摘除时误删 `if` 行导致过一次语法错误，注意按行删除要成对）。

## 9. 新站点镜像化 SOP（12 步，照着做）

1. **抓包**：列出主文档 + XHR/WS 的域名清单、请求头（尤其自定义 `x-*`）、Cookie 名。
2. **判身份链**：有没有签名头？只靠 Cookie 还是需要 `Authorization`/CSRF token？
3. **选入口形态**：Caddy SNI 复用（一个端口多站点）或 frp 中转；优先前者（路由器不用动）。
4. **搭骨架**：Cookie 注入 + 签名 + `x-*` 透传 + 上游代理设置。
5. **HTML 改写**：绝对域名 → `/_xx_/` 前缀；同时改服务端白名单。
6. **客户端 shim**：`fetch`/XHR/`window.open`/图片与脚本 setter/下载锚点/Shadow DOM。
7. **静态缓存**：**HTML 永不走缓存**；其他资源长缓存。
8. **流式通道**：`chunk_size=1`、长读超时、不缓冲的前置代理。
9. **凭据来源**：浏览器 profile 三件套（WAL）+ 失效回退。
10. **自愈与自检**：状态探测 + 全量自检脚本 + 退出码。
11. **观测面板**：至少给"出口 IP/归属地、服务状态、凭据轮换时间"。
12. **文档**：项目文档 + 教训条目 + 已完成历史。

## 10. 症状 → 大概率原因（速查）

| 症状 | 先查什么 |
|---|---|
| 卡在"思考中"、刷新答案就有 | 流式 `chunk_size` 是否被攒包；读超时是否太短 |
| 新会话不落库 / 别的设备看不到 | `SAPISIDHASH` 是否注入；`x-goog-*` 是否全透传 |
| 持续未登录（不是几秒） | `cookies.sqlite` 是否连 `-wal` 拷；缓存 mtime 是否含 WAL |
| 每隔十几分钟掉一下又回来 | `1PSIDTS` 轮换窗口 + 缓存未及时刷新 |
| 整页 502、间歇性 | 隧道连接池打满；上游长连接被掐 |
| 改了代码但页面没变化 | **HTML 是否被当静态资源缓存**（含 `immutable`） |
| 白屏 / 图标变文字 | CSP 拦截 + setter 补丁缺失 |
| 图片/视频预览正常但**下载**失败 | 原生 `<a download>` 未改写；或 `fetch(new URL())` 漏判 |
| 下载 502（Caddy 错误页） | 响应头含非 latin-1 字符（中文文件名） |
| 某块内容"响应时间太长" | 该域名没进改写白名单（`.goog`/地区域/drive） |
| iframe 一直转圈 | 宿主页三级机制：哈希校验 / targetOrigin / 补丁时序 |
| console 红字 `Refused to load the script ... googletagmanager` | 第三方统计脚本没在服务端清掉（§5.7） |
| 严格 CSP 了还担心 DNS 泄露 | 查 `rel="dns-prefetch"` / `preconnect` 里的裸 Google 域（§5.8） |

## 11. 改动纪律（血泪版）

1. **一次只改一处**，改完立刻验证；同时改三处，出问题无法归因。
2. **改前备份**（`.bak.<时间戳>`），并在回复里写清**回滚命令**。
3. **远程改代码含 `$` → 一律 base64 传输**。`ssh "python3 - << EOF"` 会被远端 shell 吃掉 `$(...)`，曾导致整页 JS 崩掉。
4. **绝不 `rm` 设备文件**：`rm -f cache/*.meta /dev/null` 把 `/dev/null` 删了，全机 systemd 服务起不来约 1 分钟。
5. **不要用"只回复 ok"自测**：游客态也能回复 ok，看不出落库问题；要用"另一台设备能否看到新会话"这种外部可观测标准。
6. **别信"服务起来了"**：验收要看真实请求的真实响应（状态码 + 字节数 + 关键响应头）。
7. **改完跑自检**（21 项），跑完看日志有没有 `Traceback`。
8. 🔴 **写文件绝不在"内容算好之前"就以 `w` 打开**。`open(p,'w').write(fn(s))` 里 `open` 先执行 → 文件立刻被清空，`fn(s)` 一旦抛异常（哪怕只是断言），**原文件已经变成 0 字节**。正确姿势：先在内存里算好并断言，再 `open(p,'w')`。本次就是这样把 `已完成历史.md` 清空的（幸而 `/srv/open-terminal/` 有前一天快照才救回来）。
9. **重要文档改动前，先确认存在可恢复的快照**（本机 `/srv/open-terminal/` 每天有整目录副本），比 `.bak` 更抗"一把清空"。
